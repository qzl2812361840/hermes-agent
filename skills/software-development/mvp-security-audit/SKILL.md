# MVP 上线安全自检宝典

来源: 张拼拼 MVP 安全宝典 (xntj.tv/ep/live-ep0027)
12 大安全域 · 88 项自检 · 按致命/高危/中危分级

## 使用方式

当用户说"安全审计"或上线前，对照下面的检查项，逐项检查整个项目（前端+后端+基础设施），
每项报告:
- ✅ 已做 / ❌ 缺失 / ⚠️ 部分有风险
- 具体证据（代码位置、配置项）
- 修复建议

## 12 大安全域

### 🔐 1. 认证与账号安全 (8项)

| # | 级别 | 问题 |
|---|---|---|
| 1.1 | 致命 | 短信验证码接口裸奔（换号即可无限发） |
| 1.2 | 高 | 验证码可被暴力猜测（6位数字不限次） |
| 1.3 | 高 | 登录接口可暴力破解/撞库（无锁定无限流） |
| 1.4 | 中 | 账号枚举（靠报错判断手机号是否注册） |
| 1.5 | 中 | 弱密码策略（123456也能注册） |
| 1.6 | 高 | JWT密钥硬编码/Token不过期不能吊销 |
| 1.7 | 中 | 登录态固定（Session Fixation） |
| 1.8 | 致命 | 第三方一键登录只信前端，没做服务端校验 |

### 🚪 2. 越权与访问控制 (7项)

| # | 级别 | 问题 |
|---|---|---|
| 2.1 | 致命 | URL id从1改2就能看别人的（IDOR水平越权） |
| 2.2 | 致命 | 普通用户直接调管理员接口（垂直越权） |
| 2.3 | 致命 | 没登录就能访问受保护接口 |
| 2.4 | 高 | 对象存储直链裸奔，有URL就能下载 |
| 2.5 | 高 | 前端藏按钮就当权限控制 |
| 2.6 | 高 | 改请求参数就绕过限制 |
| 2.7 | 中 | 邀请/重置链接token可猜可复用 |

### 🧹 3. UGC内容安全与审核 (8项)

| # | 级别 | 问题 |
|---|---|---|
| 3.1 | 致命 | 用户上传(头像/昵称/帖子)全部裸奔无审核 |
| 3.2 | 高 | 没区分先审后发和先发后审 |
| 3.3 | 高 | 只有机器审核没有人工兜底 |
| 3.4 | 中 | 垃圾广告刷屏无频率限制 |
| 3.5 | 中 | 账号注册无实名/手机验证 |
| 3.6 | 中 | 没有未成年人保护机制 |
| 3.7 | 高 | 图片/视频违规内容完全没审 |
| 3.8 | 中 | 敏感词库自己手写几个词 |

### 📎 4. 文件上传与图床 (8项)

| # | 级别 | 问题 |
|---|---|---|
| 4.1 | 致命 | 任意文件上传：木马伪装成图片 |
| 4.2 | 高 | 没校验大小和真实类型 |
| 4.3 | 高 | 图床被白嫖：上传接口成免费网盘 |
| 4.4 | 中 | 防盗链缺失：图片被到处盗用 |
| 4.5 | 致命 | 上传图片无内容审核 |
| 4.6 | 致命 | 对象存储桶公开可写 |
| 4.7 | 高 | 上传路径可遍历 |
| 4.8 | 中 | 图片元数据没清（地理位置泄露） |

### 🔌 5. 接口与API安全 (10项)

| # | 级别 | 问题 |
|---|---|---|
| 5.1 | 致命 | 接口裸奔：不用登录就能调 |
| 5.2 | 致命 | 改数字就看别人的（自增ID+越权） |
| 5.3 | 致命 | 前端传isAdmin=true就当管理员 |
| 5.4 | 高 | 接口返回夹带私货（手机号/密码哈希给前端） |
| 5.5 | 高 | 短信验证码接口无限流被刷爆 |
| 5.6 | 高 | 登录/支付接口不限速 |
| 5.7 | 高 | CORS配成* |
| 5.8 | 高 | 调试接口/Swagger裸奔 |
| 5.9 | 高 | 客服/反馈接口被当群发器 |
| 5.10 | 高 | 列表接口被爬虫批量抓数据 |

### 💉 6. 注入与前端安全 (8项)

| # | 级别 | 问题 |
|---|---|---|
| 6.1 | 致命 | SQL注入 |
| 6.2 | 致命 | 存储型XSS |
| 6.3 | 致命 | 命令注入 |
| 6.4 | 致命 | 前端硬编码密钥（F12即抄走） |
| 6.5 | 高 | CSRF |
| 6.6 | 高 | 安全响应头缺失 |
| 6.7 | 中 | 点击劫持 |
| 6.8 | 中 | 开放重定向 |

### 🤖 7. AI应用特有安全 (7项)

| # | 级别 | 问题 |
|---|---|---|
| 7.1 | 高 | 系统提示词被一句话套走 |
| 7.2 | 中 | 后端用的哪家模型被问出来 |
| 7.3 | 致命 | API Key/额度被别人花 |
| 7.4 | 高 | 红线被越狱咒语绕过 |
| 7.5 | 致命 | AI输出没做内容安全过滤 |

| 7.7 | 高 | RAG知识库越权检索 |

### 🗝️ 8. 密钥与配置管理 (6项)

| # | 级别 | 问题 |
|---|---|---|
| 8.1 | 致命 | API key/数据库密码硬编码在代码里 |
| 8.2 | 致命 | 密钥写在前端代码里 |
| 8.3 | 致命 | .env/配置文件被提交GitHub公开仓库 |
| 8.4 | 高 | 密钥泄露后没轮换 |
| 8.5 | 高 | 第三方付费key没做鉴权和限额 |
| 8.6 | 高 | DEBUG模式带上线 |

### 📋 9. 数据隐私与合规 (5项)

| # | 级别 | 问题 |
|---|---|---|
| 9.1 | 致命 | 用户隐私数据明文存储、过度收集 |
| 9.2 | 致命 | 密码明文或MD5/SHA1存储 |
| 9.3 | 高 | 全站没强制HTTPS |
| 9.4 | 中 | 第三方SDK偷偷传用户数据 |
| 9.5 | 致命 | 缺ICP备案/工商亮照/等保 |

### 🐑 10. 业务逻辑与薅羊毛 (8项)

| # | 级别 | 问题 |
|---|---|---|
| 10.1 | 致命 | 优惠券被批量领/用 |
| 10.2 | 致命 | 并发下单：同一张券被用多次 |
| 10.3 | 致命 | 价格/数量前端改服务端照收 |
| 10.4 | 高 | 签到抽奖积分被脚本刷 |
| 10.5 | 高 | 接口可重放攻击 |
| 10.6 | 高 | 退款被反复薅 |
| 10.7 | 高 | 批量注册薅奖励+短信轰炸 |
| 10.8 | 致命 | 支付回调未验签/未校验金额 |

### 🖥️ 11. 基础设施与运维 (10项)

| # | 级别 | 问题 |
|---|---|---|
| 11.1 | 致命 | 数据库端口对公网裸奔 |
| 11.2 | 高 | OSS/COS公开读且可列举 |
| 11.3 | 高 | 没有WAF/CDN裸连公网 |
| 11.4 | 高 | 无DDoS防护 |
| 11.5 | 致命 | 数据库无备份 |
| 11.6 | 高 | 无监控告警 |
| 11.7 | 中 | 无日志或日志没留存 |
| 11.8 | 中 | 依赖库大量已知漏洞 |
| 11.9 | 高 | 管理后台弱口令+暴露公网 |
| 11.10 | 致命 | SSH开放root密码登录 |

### 🚨 12. 运维就绪与应急 (3项)

| # | 级别 | 问题 |
|---|---|---|
| 12.1 | 高 | 域名/HTTPS证书到期没人管 |
| 12.2 | 高 | 无应急下线/一键熔断开关 |
| 12.3 | 中 | 被攻击后无法取证（日志不全） |

## Audit Procedure

1. Load this skill
2. For each of the 12 domains, run targeted checks against the project
3. Mark each item: ✅ passed / ❌ missing / ⚠️ partial
4. For ❌ items, provide specific fix instructions
5. Generate a summary report with pass rate and top priorities
